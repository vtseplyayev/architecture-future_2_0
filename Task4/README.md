# Задание 4. Облачная инфраструктура на IaaS и Terraform

Terraform-конфигурация инфраструктуры платформы данных «Будущее 2.0» в Yandex Cloud и диаграмма автоматизации развёртывания.
Реализует этап Э1.3 роадмапа из Задания 3; опирается на инициативы `I-2`, `I-6`, `I-9` Задания 1 и изоляцию домена `P2` из Задания 2.

## Запуск

Перед первым запуском нужно подготовить то, что Terraform создать не может: сервисный аккаунт с ролью `editor` и его авторизованный ключ.

```bash
cd Task4

# Заменить в terraform.tfvars: cloud_id, folder_id, ssh_public_key,
# lakehouse_bucket_name (имя бакета уникально глобально), trusted_ssh_cidrs
export TF_VAR_postgres_password='<пароль не короче 12 символов>'

terraform init
terraform plan
terraform apply
```

## Где задавать пароли и секреты

Ни один секрет не хранится в репозитории. В `terraform.tfvars` лежат только идентификаторы и путь к файлу ключа — сам файл находится вне рабочего дерева.

| Что | Где задаётся | Как |
|---|---|---|
| **Пароль БД метаданных** | переменная окружения | `export TF_VAR_postgres_password='...'` — минимум 12 символов, проверяется валидацией. Не нужен, если `enable_managed_postgres = false` |
| **Ключ сервисного аккаунта** | файл вне репозитория | Скачивается из консоли, кладётся в `~/.yc/terraform-sa-key.json`. В [`terraform.tfvars`](terraform.tfvars) указывается только путь в `service_account_key_file` |
| **OAuth-токен** (альтернатива ключу) | переменная окружения | `export TF_VAR_yc_token='...'`, при этом `service_account_key_file` оставить пустым |
| **Ключ доступа к бакету** | не задаётся вручную | Создаётся самим Terraform (`yandex_iam_service_account_static_access_key`) и отдаётся в output с пометкой `sensitive` |

Чего делать нельзя:

- **не вписывать пароль и токен в `terraform.tfvars`** — файл попадает в публичный репозиторий;
- **не коммитить `terraform.tfstate`** — Terraform хранит в состоянии все значения, включая помеченные `sensitive`, **открытым текстом**. Это относится и к паролю БД, и к секретному ключу бакета.

Промышленный вариант вместо переменных окружения — вынести секреты в Yandex Lockbox и читать их через data-источник.

## Облегчённый профиль

Для учебного прогона дешевле развернуть облегчённый профиль — он накладывается поверх основного и отключает управляемый кластер PostgreSQL, самую дорогую позицию:

```bash
terraform plan  -var-file=minimal.tfvars    # 24 ресурса вместо 30
terraform apply -var-file=minimal.tfvars
terraform destroy -var-file=minimal.tfvars  # сразу после снятия скриншота
```

После `apply` полезные значения доступны так:

```bash
terraform output bastion_ssh_command
terraform output -json platform_nodes
terraform output deployment_summary
```

Удаление контура: `terraform destroy`. Вторичные диски данных при этом сохраняются — у них выставлен `auto_delete = false`.

## Ключевое решение конфигурации

У подсети контура медданных **намеренно не задан** `route_table_id`. Маршрута `0.0.0.0/0` нет, значит нет и исходящего интернета: медданные не могут покинуть контур технически, а не по регламенту. Нарушить это можно только правкой инфраструктурного кода, которая пройдёт через ревью.

Подробное обоснование размеров ВМ, дисков, настроек NAT и подхода IaC — в [`justification.md`](justification.md).
